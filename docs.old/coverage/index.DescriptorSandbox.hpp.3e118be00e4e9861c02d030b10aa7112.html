3 // Runs the cxpm-descriptor-sandbox helper (applications/cxpm-descriptor-sandbox) to extract a
4 // ProjectDescriptor/ToolchainDescriptor from a compiled package.cpp/toolchain.cpp shared object
5 // out-of-process, instead of dlopen()-ing it directly inside the running cxpm process (which is
6 // what ProjectManager::load_from_manifest / ToolchainManager::load_toolchain_plugin did before
7 // this existed, and still do when the sandbox is disabled). See docs/SRS-sandbox.md.
8 //
9 // The two processes communicate over stdout/stderr pipes using the JSON descriptor codec
10 // (JsonManifest.hpp) that also backs package.json/toolchain.json -- the same serializers that
11 // let a manifest be authored as JSON are what let a sandboxed child hand a manifest back to its
12 // parent without either process dereferencing a pointer produced by the other.
13 //
14 // posix_spawn(), not fork(), is used deliberately: cxpm links a background ThreadPool
15 // (Core/Threading/ThreadPool.hpp) used by ShellManager::exec_async, and fork()-ing a
16 // multithreaded process only duplicates the calling thread -- any lock held by another thread
17 // at fork time stays locked forever in the child. posix_spawn() avoids that hazard entirely.
